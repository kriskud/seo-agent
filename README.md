# seo-agent

Лёгкий SEO-агент: набор zero-dependency Node-скриптов + systemd-таймер.
Каждый сервер несёт свою копию со своим `sites.json` и `.env`.

## Модули

| Скрипт | Что делает |
|---|---|
| `audit.mjs` | Технический аудит по sitemap: title/meta/canonical/H1/noindex, битые внутренние ссылки, orphan-страницы |
| `collect-gsc.mjs` | Search Console API → клики/показы/позиции по query+page |
| `collect-ywm.mjs` | Яндекс.Вебмастер API → ИКС, страницы в поиске, популярные запросы, диагностика (проблемы/рекомендации), статистика обхода (сайты с `yandex: true`) |
| `collect-aibots.mjs` | Логи nginx → визиты AI-краулеров (GPTBot, ClaudeBot, PerplexityBot…) и переходы из AI-сервисов по referer (сайты с `accessLog`) |
| `indexnow.mjs` | Пинг IndexNow (Яндекс/Bing) списком URL или всем sitemap (сайты с `indexnow: true`) |
| `report.mjs` | Markdown-отчёт с дельтами к прошлой неделе и SEO-возможностями → `reports/` |
| `run-weekly.sh` | Полный прогон (его дёргает `seo-agent.timer`) |

## Конфигурация

`sites.json`:

```json
{ "sites": [ { "name": "cosmodesk", "url": "https://cosmodesk.ru",
               "gsc": "sc-domain:cosmodesk.ru", "yandex": true, "indexnow": true } ] }
```

Если на сервере несколько проектов, которые не должны пересекаться одним
Google-аккаунтом, у каждого сайта укажите свой сервис-аккаунт полем
`"gscKey": "/etc/seo-agent/gsc-<site>.json"` — общий `GSC_SERVICE_ACCOUNT`
из `.env` остаётся фолбэком.

`.env` (chmod 600, не в git):

```
YANDEX_WEBMASTER_ACCESS_TOKEN=…   # + CLIENT_ID/SECRET/REFRESH_TOKEN для автообновления
GSC_SERVICE_ACCOUNT=/path/key.json  # или GOOGLE_CLIENT_ID/SECRET/REFRESH_TOKEN
INDEXNOW_KEY=…                      # файл <key>.txt должен лежать в корне сайта
```

## Данные

`data/<kind>/<site>-<date>.json` — история снимков; отчёт сравнивает два
последних. `reports/<site>-latest.md` — всегда свежий отчёт.

## Ручной запуск

```sh
./run-weekly.sh                 # полный прогон
node audit.mjs                  # только аудит
node indexnow.mjs cosmodesk     # пингануть весь sitemap
node indexnow.mjs cosmodesk https://cosmodesk.ru/guides  # конкретные URL
```

## CosmoDesk seeding — Phase 1

Отдельный ручной контур: Yandex Search → нормализация → дедупликация → JSON.
Не включён в `run-weekly.sh`; существующие SEO collectors и отчёты не меняются.
Читает только поисковую выдачу, не открывает найденные страницы и ничего не публикует.
Классификации, LLM, черновиков и очереди одобрения пока нет.

### Установка и credentials

Внешних dependencies нет; `npm install` не требуется. Используются ES modules,
встроенные `fetch`, `AbortSignal.timeout`, `node:test`. Нужен Node.js 18+;
локальная проверка выполнена на Node.js 24.19.0. Версия Node в исходном проекте не закреплена.

Новый поиск использует официальный синхронный REST API v2:
`POST https://searchapi.api.cloud.yandex.net/v2/web/search`.
Токен Яндекс.Вебмастера для него не подходит.

1. Войдите в Yandex AI Studio, выберите/создайте облако и каталог.
2. Привяжите активный платёжный аккаунт: поисковые запросы тарифицируются.
3. Создайте API-ключ через интерфейс AI Studio. Согласно quickstart вместе
   с ключом создаётся сервисный аккаунт с ролью для Search API.
4. Сохраните **секретное значение** ключа и ID того каталога, где создан ключ.
5. Добавьте в существующий `.env` в корне репозитория, без кавычек и inline-комментариев:

```dotenv
YANDEX_SEARCH_API_KEY=your-secret-api-key
YANDEX_SEARCH_FOLDER_ID=your-folder-id
YANDEX_SEARCH_DAILY_LIMIT=50
```

Можно вместо `.env` экспортировать эти переменные в окружение — окружение имеет приоритет.
Загрузка через существующий `loadEnv()` из `lib.mjs`. `.env` уже исключён из git;
права на него должны быть `600`. Новый `.env.example` не требуется.

Документация, проверенная при реализации:
- [Настройка облака, ключа и каталога](https://aistudio.yandex.ru/ru/docs/search-api/quickstart/).
- [REST WebSearch.Search v2](https://aistudio.yandex.ru/en/docs/search-api/api-ref/WebSearch/search).
- [Операторы даты и языка](https://yandex.ru/support/search/ru/query-language/search-operators).
- [Коды XML-ошибок](https://aistudio.yandex.ru/en/docs/search-api/reference/error-codes).

### Первый запуск

Из корня репозитория, после добавления credentials:

```sh
node seeding/discover.mjs --dry-run
node seeding/discover.mjs
```

Dry-run выполняет **реальные тарифицируемые API-запросы**, показывает все уникальные
результаты текущего запуска в JSON и summary, но не изменяет реестр opportunities
и позицию ротации. Кеш и расход дневного лимита сохраняются, включая dry-run.
Повторный обычный запуск может сохранить результаты из кеша без новых HTTP-запросов.

Пример формата вывода (числа иллюстративные, не результат реального запуска):

```text
CosmoDesk seeding discovery

Daily HTTP request limit: 50 (UTC)
Queries planned: 18
Queries executed: 18
API requests: 18
Results received: 143
New opportunities: 27
Duplicates skipped: 116
Errors: 0
Invalid results: 0
Cache hits: 0

Stored: /path/to/seo-agent/data/seeding/cosmodesk.json
```

`Queries executed` — начатые логические поиски, включая неудачные;
`API requests` — фактические HTTP-попытки, включая retry. `Duplicates skipped`
учитывает повторы внутри запуска и уже сохранённые URL. `Errors` считает неудачные
поиски и некорректные результаты; `Invalid results` — подмножество ошибок.
При ошибках код выхода 1, успешные результаты сохраняются. При полном отказе API
существующий реестр не перезаписывается. Пустая корректная выдача — не ошибка.

### Бюджет и свежесть

Банк запросов, домены и настройки находятся в `seeding/config/cosmodesk.json`.
Конфиг только для CosmoDesk, независимо от `sites.json`. `competitors` — справочный
список для будущей фазы, сейчас не участвует в классификации или генерации запросов.

По умолчанию `maxQueries: 18`, а дневной лимит задаётся через `.env`:

```dotenv
YANDEX_SEARCH_DAILY_LIMIT=50
```

Если переменная отсутствует, лимит также 50. Для изменения достаточно обновить
`.env` перед следующим запуском; менять код не нужно. `0` запрещает новые HTTP,
но позволяет читать кеш. Старая переменная `MAX_SEARCH_REQUESTS_PER_DAY` больше
не используется. Окно — календарные сутки UTC, не скользящие 24 часа.

`API requests` считает фактические вызовы HTTP в текущем запуске, включая retry
и неудачные попытки; блокировки лимитом и cache hits не увеличивают счётчик.
`Cache hits` выводится отдельно. Ответы кешируются на 6 часов в
`data/seeding/yandex-cache/`, по полному телу запроса (включая домен, даты и каталог),
без ключа авторизации. Пустая успешная выдача тоже кешируется, ошибки — нет.
Истёкший/повреждённый кеш считается промахом и не обходит дневной лимит.

Постоянный счётчик `data/seeding/yandex-budget.json` общий для запусков этой
установки. Под блокировкой попытка резервируется до отправки HTTP. При аварии
между резервированием и отправкой слот может остаться израсходованным: лучше
недоиспользовать бюджет, чем превысить его. Ошибка чтения/записи счётчика запрещает
HTTP. Не удаляйте и не откатывайте файл. Другие установки имеют отдельный счётчик;
это не ограничение на стороне Yandex billing.

Когда очередной cache miss требует HTTP сверх лимита, запуск штатно заканчивается:
`Errors` не увеличивается, exit code 0 при отсутствии других ошибок, частичные
результаты сохраняются, ротация не меняется. Выводится время следующего сброса.
После полуночи UTC следующий ручной/плановый запуск снова может обращаться к API;
процесс не спит до следующего дня. Cache hits до точки остановки доступны даже
при исчерпанном бюджете. Полный план — 12 поисков с доменом + 6 общих, по одной
странице из 10 результатов, без пагинации.
После полностью успешного сохранённого запуска домен каждого запроса сдвигается
на одну позицию. При полном плане из 18 поисков за 6 таких запусков будут проверены все 72 сочетания запрос/домен.
При ошибках и в dry-run ротация не меняется. При уменьшении `maxQueries` план
обрезается: часть запросов не выполняется. В минимальном режиме выполняется только
первый запрос, поэтому полного покрытия банка и общего поиска пока нет.

`freshnessDays: 7` задаёт нижнюю границу по календарной дате UTC. `minResultDate`
можно задать как `YYYY-MM-DD`; применяется более поздняя из двух нижних границ.
В запрос добавляются `site:домен`, `lang:ru` и `date:YYYYMMDD..YYYYMMDD`.
Запросы не заключаются целиком в кавычки, чтобы не требовать точного совпадения фразы.

**Ограничение свежести:** оператор `date:` описывает дату добавления страницы в
поисковую базу. Он не доказывает свежесть самого обсуждения. Неизвестная дата
публикации остаётся `publishedAt: null`; XML `modtime`, если присутствует,
сохраняется отдельно в `providerModifiedAt` в исходном формате и не подменяет
дату публикации. Даты из текста сниппетов не угадываются. Гарантированное окно
«публикация за последние 7 суток» этот источник не обеспечивает.

Между HTTP-попытками пауза не менее 1.1 секунды. Таймаут 20 секунд включает чтение
тела ответа. Для сетевых ошибок/таймаутов и HTTP 5xx допускается один повтор через
3 секунды, только если остаётся дневной бюджет. Исчерпание бюджета останавливает
поиск штатно, без отправки следующей попытки и без кода ошибки. HTTP 4xx, включая 429,
останавливают запуск без повтора и без перехода к следующему запросу. XML-ошибки
также останавливают запуск, кроме кода 15 — пустой выдачи. API body и ключи в ошибки
не выводятся. После 429 повторите запуск позже с учётом квот сервиса.

### Хранение и архитектура

В текущем репозитории SQLite и migrations отсутствуют. Для Phase 1 используется
`data/seeding/cosmodesk.json`, уже покрытый правилом `data/` в `.gitignore`:

```text
version: 1
rotation: число успешных сохранённых запусков
opportunities: массив уникальных записей
```

Каждая запись содержит `id` (SHA-256 проекта и canonical URL), `project`, `source`,
`platform`, исходный `url`, `canonicalUrl`, `title`, `snippet`, первый `query`,
`matchedQueries`, `domain`, `publishedAt`, `providerModifiedAt`, `discoveredAt`,
`lastSeenAt`, `status: discovered`. `domain` определяется по URL результата.
Повтор обновляет `lastSeenAt` и объединяет `matchedQueries`; ID, дата первого
обнаружения, исходный текст и статус сохраняются. Дополнительные будущие поля
не удаляются при обновлении записи.

Canonical URL очищается от `utm_*`, `yclid`, `gclid`, `fbclid`, `dclid`, `msclkid`,
`ysclid`, `_openstat`, `mc_cid`, `mc_eid`; параметры сортируются с сохранением порядка
повторяющихся ключей. Известные мобильные/www-алиасы VK/YouTube и www-алиасы
Dzen/Otzovik/IRecommend сводятся к основному хосту. Параметры `id`, `v`, `w`, `reply`,
`page` и неизвестные параметры сохраняются. HTTP/HTTPS, пути с/без завершающего
слеша и fragment сохраняются: без проверки редиректов нельзя безопасно считать
их одной страницей. Сокращённые ссылки и другие неизвестные алиасы пока могут
остаться отдельными записями. HTML rel=canonical не запрашивается.

Файлы модуля:
- `discover.mjs`: CLI, ограниченный план поиска и pipeline.
- `providers/yandex.mjs`: `search({ query, domain, freshnessDays, ... })` → массив
  нормализуемых результатов; getter `apiRequests` предоставляет счётчик HTTP.
- `providers/xml.mjs`: разбор фиксированного XML-формата, без DTD и внешних сущностей.
- `normalize.mjs`: URL, platform detection, схема opportunity.
- `storage.mjs`: JSON-реестр, атомарная замена через rename, блокировка писателя.
- `budget.mjs`: постоянный дневной лимит HTTP-попыток, общий для запусков и dry-run.
- `cache.mjs`: файловый кеш успешной выдачи с TTL 6 часов.
- `config/cosmodesk.json`: ручной банк запросов и бюджет.
- `seeding.test.mjs`: локальные тесты с явно синтетическими данными.

Pipeline принимает provider как объект: добавление другого источника не требует
встраивания его HTTP-логики в discovery. Реестр не является ежедневным snapshot:
это необходимо для дедупликации между запусками. Запись через временный файл
предотвращает частично записанный JSON; lock не допускает одновременных писателей.
Повреждённый реестр не сбрасывается автоматически. После аварийного завершения
может остаться `data/seeding/cosmodesk.json.lock`: удалите **только этот каталог**,
предварительно убедившись, что процесс discovery уже не работает.
Хранилище рассчитано на небольшой объём Phase 1 и целиком загружается в память.

### Проверки

```sh
node --test seeding/seeding.test.mjs
node --check seeding/discover.mjs
node --check seeding/providers/yandex.mjs
```

Тесты не вызывают реальный API: они проверяют XML, HTTP-ошибки/таймауты, бюджет,
ротацию, URL, dedupe между запусками, сохранение статуса, атомарное хранение,
блокировку, частичный отказ, отсутствие записи opportunities в dry-run и
постоянный дневной лимит: повторный запуск, retries, смена суток UTC и fail-closed.
После добавления credentials нужно проверить реальный формат выдачи, доступы/квоты,
работу операторов и качество/свежесть найденных обсуждений. До этой проверки
классификатор и следующие фазы не добавляются.

### Обязательное ограничение для будущего Telegram listener

До реализации Telegram прочитать [требования безопасности](seeding/TELEGRAM-SECURITY.md).
Нужны отдельный Linux user, secrets/session вне repository/application directory,
права `0700`/`0600`, fail-closed проверки и явный allowlist групп/каналов.
Telegram credentials запрещены в общем `.env`, git, логах и CLI arguments.
Сначала пользователь проверяет proposed storage, permissions и systemd unit;
только затем можно подключать существующую сессию. Telegram сейчас не реализован.
